# 服务验证记录

本文件记录本环境的服务验证方式与**实验当时的实测结果**，用于复现时逐项比对。

## 记录说明

- **结果来源**：`OpenStack 私有云平台搭建与运维/` 下六份课程实训报告的终端截图，实验时间 2026-04-18 至 2026-05-22。
- **验证方式**：报告中每个组件都按「端口监听 → 服务状态 → 业务命令」三层验证，本文件沿用该三层结构。
- **复现提示**：下表「实测结果」是历史记录，不代表当前状态；重建环境后应重新执行「验证命令」列并对比「期望结果」列。
- 所有 `openstack` 命令执行前需先加载环境变量：`. admin-login`（【实测】用法）。

## 四、故障与处理记录

以下问题来自六份实训报告「五、实训总结」中的实录，为该项目真实踩过的坑。

### 4.1 RabbitMQ 认证失败

- **现象**：各组件连接消息队列时报认证错误，服务无法启动。
- **处置**：重新执行 `rabbitmqctl add_user openstack 000000` 并 `set_permissions ".*" ".*" ".*"`，确认组件配置中的 `transport_url = rabbit://openstack:000000@controller` 与之一致。
- **来源**：实训报告03 总结「遇到 RabbitMQ 认证失败……通过日志分析和配置调整逐一解决」。

### 4.2 数据库同步失败

- **现象**：`nova-manage db sync`、`neutron-db-manage upgrade head` 等初始化命令报错。
- **处置**：核对 `nova_api`、`nova_cell0`、`nova` 三个库是否都已建好并授权；确认 `localhost` 与 `%` 两条授权都存在；检查配置文件中连接串的密码与库名。
- **来源**：实训报告03、报告04 总结。

### 4.3 Neutron DHCP 与 VMware DHCP 冲突

- **现象**：云主机拿不到 IP 地址。
- **处置**：在 VMware「虚拟网络编辑器」中**关闭 VMnet8 的 DHCP 服务**，由 Neutron 的 dnsmasq 独占地址分配。
- **来源**：实训报告05 总结「深入理解了 Flat 类型网络需独占物理网卡的特性，以及 Neutron DHCP 服务与 VMware DHCP 服务共存时的冲突问题」。

### 4.4 etcd 配置必须使用 IP 而非主机名

- **现象**：按文档用主机名填写 etcd 地址后服务异常。
- **处置**：`ETCD_LISTEN_*` / `ETCD_INITIAL_*` 全部改为 `192.168.10.10`。注意这与其余组件不同——Keystone 等服务端点用主机名 `controller`，etcd 必须用 IP。
- **来源**：实训报告02 总结「特别注意了配置文件中不能使用主机名而必须用 IP 地址的要点」。

### 4.5 Flat 网络独占物理网卡

- **现象**：Flat 类型网络创建后，外部网卡无法再承载管理流量。
- **处置**：属 Flat 网络的固有约束，需为 provider 网络单独规划一块网卡（本环境为 `ens34`）。若需复用管理网卡，应改用 VLAN 或 VXLAN。
- **来源**：实训报告05 总结。

### 4.6 观察到的无害告警

以下输出在实验中出现但不影响功能，复现时无需处理：

| 告警 | 出现位置 | 说明 |
|---|---|---|
| `/etc/rc.d/rc.local is not marked executable` | 重启时控制台输出 | 系统启动脚本权限提示，与 OpenStack 无关 |
| `Warning: (1831, 'Duplicate index `block_device_mapping_instance_uuid_virtual_name_device_name_idx`')` | `nova-manage db sync` | MySQL 8 下的索引重复告警，Train 已知问题 |
| `301 Moved Permanently` | `wget cloud.centos.org` | 镜像站重定向，`wget` 会自动跟随 |
