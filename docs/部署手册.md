# 部署手册

> 本文档依据 `OpenStack 私有云平台搭建与运维/云计算技术与应用_实训报告0{1..6}.docx` 中的步骤结构与终端截图整理，用于从零重建本环境。行内标注 `【实测】` 的取值直接来自截图；未标注的命令为按 openEuler / OpenStack Train 通行流程补全，复现时以实际输出为准。

## 0. 环境约定

| 项 | 值 |
|---|---|
| 操作系统 | openEuler 22.03 LTS SP3（最小化安装） |
| OpenStack | Train，本地 ISO 源 `openStack-train.iso` 【实测】 |
| Region | `RegionOne` 【实测】 |

## 1. 环境准备

### 1.1 创建虚拟机（实训报告01）

Workstation「文件 → 新建虚拟机 → 自定义（高级）」，两台节点采用相同规格：

| 配置项 | 值 |
|---|---|
| 硬件兼容性 | Workstation 17.x |
| 客户机操作系统 | Linux / 其他 5.x 内核 64 位 |
| 处理器 | 2 vCPU |
| 内存 | 4096 MB |
| 网络类型 | 先选「仅主机」，创建后再添加一块「NAT」网卡 |
| 磁盘 | SCSI（LSILogic），40 GB |
| CD/DVD | `openEuler-22.03-LTS-SP3-x86_64-dvd.iso` |

**必须先开启虚拟化引擎**，否则后续无法创建 KVM 云主机：虚拟机设置 → 处理器 → 勾选「虚拟化 Intel VT-x/EPT 或 AMD-V/RVI」。

### 1.2 配置虚拟网络

进入「编辑 → 虚拟网络编辑器」（需管理员权限）：

| 网络 | 类型 | 网段 | 备注 |
|---|---|---|---|
| VMnet1 | 仅主机 | 192.168.10.0/24 | 宿主侧 192.168.10.1 |
| VMnet8 | NAT | 192.168.20.0/24 | 网关 192.168.20.2 |

> ⚠️ 关键一步：**关闭 VMnet8 的 DHCP 服务**。实训05记载，Neutron 的 DHCP 与 VMware 自带 DHCP 共存会产生地址冲突，导致云主机拿不到 IP。

### 1.3 安装 openEuler 并完成基础设置（实训报告01）

安装过程中设置 root 密码、选择「最小安装」。首次进入系统后：

```bash
# 1) 修改主机名（控制节点 / 计算节点分别执行）
[controller]# hostnamectl set-hostname controller
[compute]#    hostnamectl set-hostname compute

# 2) 配置静态 IP（控制节点示例，计算节点改为 .20）
[controller]# vi /etc/sysconfig/network-scripts/ifcfg-ens33
```

管理网卡 `ens33` 配置：

```ini
TYPE=Ethernet
BOOTPROTO=static
NAME=ens33
DEVICE=ens33
ONBOOT=yes
IPADDR=192.168.10.10
PREFIX=24
```

外部网卡 `ens34` 配置（实测自 `ifcfg-ens34` 截图）：

```ini
TYPE=Ethernet
BOOTPROTO=static          # 【实测】
DEFROUTE=yes              # 【实测】
NAME=ens34                # 【实测】
DEVICE=ens34              # 【实测】
ONBOOT=yes                # 【实测】
IPADDR=192.168.20.20      # 计算节点值【实测】；控制节点为 192.168.20.10
GATEWAY=192.168.20.2      # 【实测】
DNS1=114.114.114.114      # 【实测】
DNS2=8.8.8.8              # 【实测】
```

```bash
# 3) 生效并验证
nmcli connection reload
systemctl restart network
ip addr show

# 4) 关闭防火墙（两个节点都要执行）【实测】
systemctl stop firewalld
systemctl disable firewalld
systemctl status firewalld     # 期望 Active: inactive (dead)

# 5) 使用 MobaXterm 从宿主机 SSH 登录 192.168.10.10 / 192.168.10.20
```

## 2. 克隆计算节点与域名解析（实训报告02）

### 2.1 克隆虚拟机

关闭控制节点 → 右键 →「管理 → 克隆」→ 选择「虚拟机中的当前状态」→「创建完整克隆」→ 命名 `计算节点`。

克隆后**必须先改 IP** 再启动两台机器，同一网络内出现重复 IP 会导致通信异常。

### 2.2 配置 /etc/hosts

两个节点写入相同内容：

```bash
[controller]# vi /etc/hosts
```

```
127.0.0.1   localhost localhost.localdomain
192.168.10.10  controller
192.168.10.20  compute
```

验证：

```bash
ping -c 4 compute
# 期望：64 bytes from compute (192.168.10.20) ... 0% packet loss 【实测】
```

> 该环境所有服务端点使用主机名而非 IP，`/etc/hosts` 写错会导致 Keystone 端点解析失败、各组件无法互认，是最高频的故障点。

### 2.3 检查点：拍摄快照

两台机器关机后各拍一份快照，命名如「基础环境完成」。后续每完成一个大阶段重复此操作——本项目即按此产出 `keystone完成`、`实验三完成`、`Neutron完成`、`虚拟网络和子网` 四个快照。

## 3. 搭建本地软件源（实训报告02）

内网环境无法直连公网源，需用 `openStack-train.iso` 搭建本地仓库。

### 3.1 挂载 ISO（控制节点）

```bash
[controller]# mkdir -p /opt/openStack
[controller]# mount -o loop /opt/openStack-train.iso /opt/openStack
[controller]# vi /etc/fstab      # 追加开机自动挂载
```

```
/opt/openStack-train.iso /opt/openStack iso9660 defaults 0 0
```

> `fstab` 该行内容为【实测】。

### 3.2 清理并重建 repo 文件

```bash
[controller]# mkdir -p /etc/yum.repos.d/bak
[controller]# mv /etc/yum.repos.d/*.repo /etc/yum.repos.d/bak/   # 备份原有源
[controller]# vi /etc/yum.repos.d/openStack.repo
```

```ini
[OpenStack_Train]
name=OpenStack_Train
baseurl=file:///opt/openStack
enabled=1
gpgcheck=0
```

```bash
[controller]# yum clean all
[controller]# yum makecache
[controller]# yum repolist
```

期望结果（【实测】）：

```
repo id            repo name
OS                 OS
everything         everything
update             update
OpenStack_Train    OpenStack_Train
EPOL               EPOL
```

> `OS` / `everything` / `update` / `EPOL` 来自 openEuler DVD 自带的 repo 目录，`OpenStack_Train` 来自 ISO。

### 3.3 用 FTP 把仓库共享给计算节点

计算节点不挂载 ISO，通过控制节点的 FTP 取包。

```bash
# 控制节点：安装并配置 vsftpd
[controller]# yum -y install vsftpd
[controller]# vi /etc/vsftpd/vsftpd.conf
```

```
anonymous_enable=YES
anon_root=/opt/openStack
```

```bash
[controller]# systemctl start vsftpd
[controller]# systemctl enable vsftpd
```

```bash
# 计算节点：直接从控制节点复制 repo 配置文件【实测】
[compute]# cd /etc/yum.repos.d
[compute]# scp root@controller:/etc/yum.repos.d/openStack.repo ./
[compute]# yum clean all && yum makecache
```

复制后需把 `baseurl` 改为指向 FTP：

```ini
baseurl=ftp://controller/
```

> `scp` 过程显示 `OpenStack.repo 100% 455 112.3KB/s`，为【实测】；`baseurl` 的具体路径以 ISO 内目录结构为准，本环境 repo id 为 `OpenStack_Train`。

### 3.4 升级软件包并安装客户端

```bash
# 两个节点都执行
[controller]# yum upgrade -y
[compute]#    yum upgrade -y

# 安装 OpenStack 管理客户端【实测 4.0.2】
[controller]# yum -y install python-openstackclient
[compute]#    yum -y install python-openstackclient
```

## 4. 时间同步 Chrony（实训报告02）

OpenStack 各组件依赖时间一致，否则 Token 校验、消息队列会失败。

```bash
# 控制节点作为 NTP 服务器
[controller]# yum -y install chrony
[controller]# vi /etc/chrony.conf
```

```
server 0.pool.ntp.org iburst
allow 192.168.10.0/24
local stratum 10
```

```bash
[controller]# systemctl enable --now chronyd
```

```bash
# 计算节点同步控制节点
[compute]# yum -y install chrony
[compute]# vi /etc/chrony.conf
```

```
server controller iburst
```

```bash
[compute]# systemctl enable --now chronyd
[compute]# chronyc sources -v
```

验证：`ss -tlnup` 可见 chronyd 监听 `127.0.0.1:323`、`[::1]:323`（【实测】）。

## 5. 基础服务（实训报告02）

以下四项在**控制节点**安装。计算节点仅在需要时安装 MariaDB 客户端。

### 5.1 MariaDB

```bash
[controller]# yum -y install mariadb mariadb-server python3-PyMySQL
[controller]# vi /etc/my.cnf.d/mariadb-server.cnf      # [实测步骤：编辑数据库文件]
```

在 `[mysqld]` 段加入：

```ini
bind-address = 192.168.10.10
default-storage-engine = innodb
innodb_file_per_table = on
max_connections = 4096
collation-server = utf8_general_ci
character-set-server = utf8
```

```bash
[controller]# systemctl enable --now mariadb
[controller]# mysql_secure_installation        # 初始化数据库【实测步骤】
[controller]# mysql -uroot -p
```

后续每个组件都按「建库 → 授权」两步执行，口令统一 `000000`：

```sql
CREATE DATABASE keystone;
GRANT ALL PRIVILEGES ON keystone.* TO 'keystone'@'localhost' IDENTIFIED BY '000000';
GRANT ALL PRIVILEGES ON keystone.* TO 'keystone'@'%' IDENTIFIED BY '000000';
```

> 逐组件授权语句为【实测】，例如 nova：
> ```
> GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'localhost' IDENTIFIED BY '000000';
> GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'%' IDENTIFIED BY '000000';
> ```
> 每个库都建 `localhost` 与 `%` 两条授权，否则组件跨节点访问会失败。

### 5.2 RabbitMQ

```bash
[controller]# yum -y install rabbitmq-server        # [实测 3.9.23]
[controller]# systemctl enable --now rabbitmq-server

# 建用户并授权【实测】
[controller]# rabbitmqctl add_user openstack 000000
[controller]# rabbitmqctl set_permissions openstack ".*" ".*" ".*"

# 检查【实测】
[controller]# rabbitmqctl list_permissions openstack
[controller]# ss -tlnup | grep -E '5672|25672'
```

### 5.3 Memcached

```bash
[controller]# yum -y install memcached python-memcached    # [实测 1.6.12]
[controller]# vi /etc/sysconfig/memcached
```

```ini
OPTIONS="-l 127.0.0.1,::1,controller"
```

```bash
[controller]# systemctl enable --now memcached
[controller]# netstat -tnlup | grep 11211        # 期望 LISTEN 7763/memcached 【实测】
```

### 5.4 etcd

```bash
[controller]# yum -y install etcd
[controller]# vi /etc/etcd/etcd.conf
```

关键参数（以下为【实测】值）：

```ini
#[member]
ETCD_NAME=controller
ETCD_DATA_DIR="/var/lib/etcd/default.etcd"
ETCD_LISTEN_PEER_URLS="http://192.168.10.10:2380"
ETCD_LISTEN_CLIENT_URLS="http://192.168.10.10:2379,http://127.0.0.1:2379"

#[cluster]
ETCD_INITIAL_ADVERTISE_PEER_URLS="http://192.168.10.10:2380"
ETCD_INITIAL_CLUSTER="controller=http://192.168.10.10:2380"
ETCD_INITIAL_CLUSTER_STATE="new"
ETCD_INITIAL_CLUSTER_TOKEN="etcd-cluster-01"
ETCD_ADVERTISE_CLIENT_URLS="http://192.168.10.10:2379"
```

```bash
[controller]# systemctl enable --now etcd
[controller]# netstat -tnlup | grep etcd
# 期望：192.168.10.10:2379、127.0.0.1:2379、192.168.10.10:2380 均 LISTEN 【实测】
```

> ⚠️ 实训总结明确记录：**配置文件中不能用主机名，必须写 IP 地址**。此为该组件最常见的踩坑点。

## 6. Keystone 认证服务（实训报告03）

```bash
[controller]# yum -y install openstack-keystone httpd mod_wsgi
# [实测] openstack-keystone 16.0.2 / httpd 2.4.51 / python3-mod_wsgi 4.9.1
```

建库授权见 5.1，库名 `keystone`。

### 6.1 配置文件 /etc/keystone/keystone.conf

```ini
[database]
connection = mysql+pymysql://keystone:000000@controller/keystone

[token]
provider = fernet
```

### 6.2 初始化数据库与密钥库

```bash
[controller]# su -s /bin/sh -c "keystone-manage db_sync" keystone

# 初始化 Fernet 密钥库【实测】
[controller]# keystone-manage fernet_setup --keystone-user keystone --keystone-group keystone
[controller]# keystone-manage credential_setup --keystone-user keystone --keystone-group keystone
```

`fernet_setup` 的期望输出（【实测】）：在 `/etc/keystone/fernet-keys/` 下创建密钥 `0`、`1`，并提示 `Starting key rotation with 1 key files`、`Promoted key 0 to be the primary: 1`。

### 6.3 初始化身份认证信息

```bash
[controller]# keystone-manage bootstrap \
  --bootstrap-password 000000 \
  --bootstrap-admin-url http://controller:5000/v3/ \
  --bootstrap-internal-url http://controller:5000/v3/ \
  --bootstrap-public-url http://controller:5000/v3/ \
  --bootstrap-region-id RegionOne
```

### 6.4 配置 Web 服务

```bash
[controller]# yum -y install httpd mod_wsgi          # 为 Apache 增加 WSGI 支持
[controller]# vi /etc/httpd/conf/httpd.conf
```

关键行（【实测】）：

```
ServerName controller
```

```bash
[controller]# ln -s /usr/share/keystone/wsgi-keystone.conf /etc/httpd/conf.d/
[controller]# systemctl enable --now httpd
[controller]# systemctl restart httpd
```

### 6.5 环境变量文件

```bash
[controller]# vi /root/admin-login
```


后续所有 `openstack` 命令前先执行 `. admin-login`（【实测】用法）。

### 6.6 验证

## 7. Glance 镜像服务（实训报告03）

```bash
[controller]# yum -y install openstack-glance
```

建库：`glance`。

### 7.1 配置文件 /etc/glance/glance-api.conf

```ini
[database]
connection = mysql+pymysql://glance:000000@controller/glance

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = glance

[paste_deploy]
flavor = keystone

[glance_store]
stores = file,http
```

> 实训报告中有一步「备份配置文件 → 删除所有注释和空行 → 编辑新文件」，即 `grep -Ev '^#|^$' glance-api.conf > glance-api.conf.new`，便于逐项核对。

```bash
[controller]# su -s /bin/sh -c "glance-manage db_sync" glance
[controller]# mysql -uroot -p -e "use glance; show tables;"     # 检查数据库
```

```bash
[controller]# openstack service create --name glance --description "OpenStack Image" image

# 三类端点【实测：public 端点 url = http://controller:9292】

[controller]# openstack endpoint create --region RegionOne image internal http://controller:9292
[controller]# openstack endpoint create --region RegionOne image admin    http://controller:9292
```

### 7.4 启动与验证

```bash

[controller]# systemctl status openstack-glance-api
# 期望：Active: active (running) 【实测】

```

### 7.5 制作镜像


## 9. Nova 计算服务（实训报告03）

### 9.1 控制节点：安装与建库

```bash
[controller]# yum -y install openstack-nova-api openstack-nova-conductor \
                            openstack-nova-novncproxy openstack-nova-scheduler
```

建三个库并授权（【实测】语句）：

```sql
CREATE DATABASE nova_api;
CREATE DATABASE nova;
CREATE DATABASE nova_cell0;

GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'localhost' IDENTIFIED BY '000000';
GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'%'         IDENTIFIED BY '000000';
GRANT ALL PRIVILEGES ON nova_cell0.* TO 'nova'@'localhost' IDENTIFIED BY '000000';
GRANT ALL PRIVILEGES ON nova_cell0.* TO 'nova'@'%'        IDENTIFIED BY '000000';
GRANT ALL PRIVILEGES ON nova.* TO 'nova'@'localhost'      IDENTIFIED BY '000000';
GRANT ALL PRIVILEGES ON nova.* TO 'nova'@'%'              IDENTIFIED BY '000000';
```

### 9.2 配置文件 /etc/nova/nova.conf

控制节点与计算节点大部分相同，差异在 `[vnc]` 与 `[libvirt]` 段。


## 14. 部署顺序速查

组件间存在依赖，顺序不可颠倒：

```
1. 系统与网络（双网卡、hosts、防火墙关闭）
2. 本地软件源（ISO 挂载 + FTP 共享）
3. Chrony → MariaDB → RabbitMQ → Memcached → etcd
4. Keystone        ← 所有组件的认证前提，必须最先
5. Glance          ← Nova 依赖镜像
6. Placement       ← Nova 依赖资源调度
7. Nova（控制 → 计算 → discover_hosts）
8. Neutron（控制 → 计算）→ 重启 nova-api
9. Dashboard
10. Cinder（控制 → 计算存储节点 → 重启 nova-api）
11. 网络与云主机运维
```

每完成一步，用 [docs/服务验证记录.md](docs/服务验证记录.md) 中对应的检查项确认后再进入下一步。
